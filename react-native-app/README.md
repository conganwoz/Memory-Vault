# Kindred — React Native (Expo)

A fully functional React Native port of the **Kindred Shared Memory Vault** web app.
Built with [Expo](https://expo.dev) and React Navigation, backed by the
**Elixir/Phoenix API** in `../backend` (auth, albums, photo uploads, recaps,
invites). The app talks to the backend over plain HTTP/JSON with a JWT.

## Features

| Feature | Mobile implementation |
| --- | --- |
| Splash + auth gating | Animated splash, auto-routes to Login/Home based on auth state |
| Email sign-in / sign-up | `POST /api/auth/signin` / `signup` with friendly error messages |
| Google sign-in | `expo-auth-session` Google provider → `POST /api/auth/google` |
| Album list ("book stack" cards) | Fetched from `GET /api/albums`, refreshed on focus |
| Create vault | Title, native date picker, privacy tier, cover photo picker |
| Album detail timeline | Parallax hero header, photos grouped by `timestampLabel`, staggered grid |
| Photo viewer | Zoomable image, heart reactions via `POST /api/photos/:id/reactions` |
| Upload moments | Multi-select gallery picker → `POST /api/albums/:id/photos` |
| Live camera capture | `expo-camera` with shutter/flash animations and background upload |
| Invite screen | Real invite code from `POST /api/albums/:id/invite`, copy + share |
| AI memory recap | Generated by the backend (Gemini, with local fallback) |
| Profile & stats | Live stats computed from your vaults, settings rows, sign-out |

## Quick start

**Prerequisites:** Node.js 18+, the
[Expo Go app](https://expo.dev/go) on your phone (or an iOS/Android emulator),
and the backend running (see `../backend/README.md` — `docker compose up` or
`mix phx.server`).

```bash
cd react-native-app
npm install
npx expo start
```

Scan the QR code with Expo Go (Android) or the Camera app (iOS).

### Type checking

```bash
npm run typecheck
```

## API configuration (dev on LAN / prod)

The API base URL is resolved in `lib/config.ts` with this priority:

1. **`EXPO_PUBLIC_API_URL`** env var — highest priority, great for prod builds:
   ```bash
   EXPO_PUBLIC_API_URL=https://api.kindred.app npx expo start
   ```
2. **`expo.extra.apiBaseUrl` in `app.json`** — the "config file" for dev
   (your machine's LAN IP + the backend port) and prod:
   ```json
   "extra": {
     "apiBaseUrl": "http://192.168.1.51:4008",
     "apiPort": 4008
   }
   ```
3. **Auto-derived from the Expo dev-server host** — when both are empty, the
   app reuses the machine's LAN IP from Expo's `hostUri` and appends
   `apiPort` (default `4008`). This makes dev over LAN work with zero config.
4. Fallback: `http://localhost:4008`.

> **Dev over LAN:** run the backend (e.g. `docker compose up` in `../backend`),
> find your IP (`ipconfig getifaddr en0`), then set `apiBaseUrl` in `app.json`
> to `http://<your-ip>:4008` and restart `npx expo start -c`. Your phone must
> be on the same Wi-Fi network. Emulator note: Android emulators reach the host
> via `10.0.2.2`, iOS simulators via `localhost`.

### Google sign-in

For Google sign-in you need OAuth client IDs from
[Google Cloud Console](https://console.cloud.google.com/apis/credentials)
(APIs & Services → Credentials → Create credentials → OAuth client ID):

- **Web application** client → required for every platform.
- **iOS** client → required to launch Google sign-in on iOS (otherwise
  expo-auth-session throws `Client Id property iosClientId must be defined`).
- **Android** client → required for Android.

Put them in `app.json` under `expo.extra`:

```json
"extra": {
  "googleWebClientId": "xxxx.apps.googleusercontent.com",
  "googleIosClientId": "xxxx.apps.googleusercontent.com",
  "googleAndroidClientId": "xxxx.apps.googleusercontent.com"
}
```

Then restart the dev server (`npx expo start -c`). The backend must also accept
these IDs via `GOOGLE_CLIENT_IDS` (see `../backend/README.md`). Until both are
configured, email sign-in always works; the Google button explains what's missing.


## Data model & storage

All data lives in the backend's PostgreSQL database (see `../backend`). The JSON
shapes match the app's types in `lib/types.ts`:

```
User    userId, displayName, email, photoURL, createdAt
Album   id, title, description, coverPhotoURL, eventDate, ownerId,
        members[], photoCount, privacy, createdAt
Photo   id, albumId, uploaderId, uploaderName, url, caption, type,
        reactions{heart}, timestampLabel, createdAt
Recap   id, albumId, title, summary, photoUrls, createdAt
```

Uploaded images are stored on the backend and served at
`/uploads/albums/:albumId/:file` (relative URLs are resolved to absolute via
`lib/config.ts` → `resolveAssetUrl`).

## AI recaps

Recaps are generated by the backend's `POST /api/albums/:id/recaps/generate`
(which calls Gemini when `GEMINI_API_KEY` is set, with a warm local fallback).
The app shows a loading ring while generating and falls back to a local summary
only if the backend is unreachable.
